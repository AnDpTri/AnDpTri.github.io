My part

  • Individual capstone: designed and built the backend, the web app, the AI agent and the tests on my own.

Main features

  • Accounts: registration, login and logout, refresh tokens, password reset, multi-device sessions, OAuth.
  • Money: wallets with balances derived from the ledger, a category tree, income, expense and transfer transactions, CSV export and receipt upload with permissions.
  • Planning: budgets, savings goals, recurring transactions, bill reminders, automation rules, family collaboration, reports.
  • Quality: unified response envelope, central error handling, OpenAPI documentation, migrations with indexes and check constraints.

The AI agent

The assistant is an agent in one chat window. DeepSeek or OpenAI decides whether to answer directly or call a tool (native tool calling); there is no local fallback model, and without a provider key the rest of the app still works. The backend, not the prompt, enforces access rights, ownership checks, confirmation and undo.

  • Read tools (search and summarize transactions, upcoming bills, history, export) run immediately; tools that change data only create a pending action with a preview.
  • The user confirms within 30 minutes; the backend rechecks ownership, runs the change in a transaction and stores undo data. Confirm, cancel and undo are audited without storing secrets.
  • A turn uses at most 4 model-tool rounds and 10 tool calls; tool errors go back to the model so it can fix its arguments or ask the user; actions are rate limited.
  • Conversations are stored with summaries, and long-term memory only holds facts the user confirmed. If the account language is Vietnamese but the model answers in another language, the backend asks for a rewrite instead of showing it.

Stack

  • TypeScript 5.9, Express 4, Prisma 6, Zod 3, PostgreSQL 17; React front end.
  • Docker Compose starts three services: the database, a mail inbox for development (Mailpit) and the API with the web app; it waits for the database, runs migrations and creates a test account.
  • Vitest and Supertest for unit and API tests (with an 80% coverage gate), Playwright for UI journeys.

Testing

158 Vitest tests cover the whole backend source except the process start-up file, and fail the build if statements, branches, functions or lines drop below 80%. Current figures: statements 97%, branches 88%, functions 97%, lines 99%. On top of that: 119 end-to-end API flows against the running stack, 25 UI journeys on desktop and mobile, a test group for the agent against a real database without calling the AI, and agent scenarios with a real provider that are skipped when no key is set.
